Grab the latest installer from the
**[Releases page](https://github.com/Intevity/sentinel/releases/latest)**, or pick your platform
directly. The daemon is bundled inside the app — there is nothing else to install.

| Platform                          | Format        |
| --------------------------------- | ------------- |
| **macOS** — Apple Silicon (M1–M5) | `.dmg`        |
| **macOS** — Intel                 | `.dmg`        |
| **Windows** 10/11                 | `.msi` / NSIS |
| **Linux** (Debian/Ubuntu)         | `.deb`        |
| **Linux** (Fedora/RHEL)           | `.rpm`        |
| **Linux** (portable)              | `.AppImage`   |

## Prerequisites

- macOS 12+, Windows 10+, or a Linux distribution with the libraries listed below.
- [Claude Code](https://claude.com/claude-code) installed.
- Node.js 24+ is required by Claude Code itself; the Sentinel daemon ships its own runtime, so you
  do **not** need Node installed for Sentinel.

## Install

<Tabs syncKey="os">
  <TabItem label="macOS">
    Open the `.dmg` and drag **Sentinel** to your Applications folder.

    <Aside type="tip" title="Release builds are signed and notarized">
    Official macOS releases are signed with a Developer ID certificate and notarized by Apple, so
    they open with a normal double-click — no "unidentified developer" prompt and no `xattr`
    workaround. (If you build from source locally, your build is only ad-hoc signed; right-click →
    **Open** once to launch it.)
    </Aside>

    ![Sentinel's first-launch activation banner](/sentinel/screenshots/first-launch.png)

  </TabItem>

<TabItem label="Windows">
  Run the NSIS `-setup.exe` (recommended) or the `.msi`. Released builds are
  Authenticode-signed.

<Aside type="tip" title="Prefer the -setup.exe for auto-updates">
  The NSIS installer installs per-user and needs no elevation, so in-app updates apply without a
  User Account Control prompt. The `.msi` installs per-machine, so every update needs approval — and
  if that prompt is dismissed or blocked by policy, Windows gives the updater no way to report it.
  Sentinel detects the failure on the next launch and shows a banner with a manual download link,
  but the `-setup.exe` avoids the situation entirely.
</Aside>

  <Aside type="caution" title="Claude Code inside WSL is not supported yet">
  Sentinel is a native Windows app and assumes Claude Code is too. If your Claude Code lives inside
  a WSL distribution, two things break:

- **Activation writes the wrong file.** It patches `%USERPROFILE%\.claude\settings.json`, which
  WSL's Claude Code never reads — it reads `~/.claude/settings.json` inside the distro.
- **The proxy is unreachable.** The daemon listens on `127.0.0.1:47284` on the Windows host. WSL2
  can only reach that with [mirrored
  networking](https://learn.microsoft.com/windows/wsl/wsl-config#configuration-settings-for-wslconfig)
  (`networkingMode=mirrored` in `%USERPROFILE%\.wslconfig`).

The tell is that account usage percentages update normally while the **Metrics** and **Optimize**
tabs stay empty — usage is polled over OAuth and never touches the proxy. For now, run Claude
Code on Windows itself. First-class WSL support is being scoped.

  </Aside>
</TabItem>

  <TabItem label="Linux">
    Install the `.deb`/`.rpm` for your distro, or run the portable `.AppImage`.

    **Required system libraries** — `webkit2gtk-4.1` powers the app window and `libsecret` is the
    keychain backend used to store credentials:

    | Distro | Command                                              |
    | ------ | ---------------------------------------------------- |
    | Arch   | `sudo pacman -S webkit2gtk-4.1 libsecret`            |
    | Debian | `sudo apt install libwebkit2gtk-4.1-0 libsecret-1-0` |
    | Fedora | `sudo dnf install webkit2gtk4.1 libsecret`           |

    **Wayland** is supported natively — no manual configuration. The app detects Wayland at
    startup and disables WebKit's DMA-BUF renderer, which triggers a protocol error (`EPROTO`) on
    some compositors.

  </TabItem>
</Tabs>

## First launch

<Steps>

1. **Launch Sentinel** from your Applications folder (or Start menu / app launcher). The tray icon
   appears in the menu bar / system tray, and the daemon starts automatically.

2. **Click "Activate Sentinel"** in the banner that appears on first launch. This writes
   `ANTHROPIC_BASE_URL=http://localhost:47284` plus OTEL environment variables into
   `~/.claude/settings.json` — the only required setup step.

3. **Restart Claude Code.** From this point on, every Claude Code session routes through the
   Sentinel proxy.

4. **Enroll accounts** via the tray app → **Add Account**. Sentinel opens a terminal running
   `claude setup-token` and captures the token it prints. Complete the browser sign-in it
   launches, making sure you're signed in to the org you want to add — the token is scoped to
   whichever org claude.ai is currently showing.

</Steps>

The [quick start](/sentinel/docs/getting-started/quick-start/) walks through these steps in more
detail.

## Verify the daemon is running

The daemon exposes a health endpoint on its proxy port:

```sh
curl http://localhost:47284/health
# {"status":"ok","pid":12345}
```

If this errors or times out, the daemon is not running — relaunch the app, or check
`~/.sentinel/daemon.log`. The in-app **⋯ menu** also shows live pid and uptime.

## Uninstall

Open the tray app → **⋯ menu → Uninstall Sentinel…**. The dialog lets you choose whether to also
delete local data (usage history, rate-limit cache, keychain credentials). Uninstalling:

- Removes the Sentinel environment variables from `~/.claude/settings.json`, so Claude Code goes
  back to calling `api.anthropic.com` directly.
- Optionally wipes `~/.sentinel/` and every `Sentinel-credentials` keychain entry.
- Shuts the daemon down and quits the app.

The app itself remains in `/Applications` (or your install location) — trash it normally to remove
the binaries too.
