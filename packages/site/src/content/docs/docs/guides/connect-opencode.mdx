Sentinel can sit in front of [opencode](https://opencode.ai), so its Anthropic traffic gets the same
request log, security scanning, permission rules, and cache-TTL handling as Claude Code.

<Aside type="caution" title="Whose credentials opencode uses">
  It depends on how opencode signs in to Anthropic:

- **Anthropic API key** — opencode keeps using **your own key**. Sentinel forwards it untouched
  and does not swap in a pooled account; see
  [Why API-key requests are not pooled](#why-api-key-requests-are-not-pooled).
- **Claude subscription via the `opencode-claude-auth` plugin** — requests present Claude Code's
  identity, so Sentinel serves them from **its account pool**, the same as Claude Code. See
  [Subscription plans via community plugins](#subscription-plans-via-community-plugins).
  </Aside>

## What you get

| Feature                                            | With opencode                                                                          |
| -------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Request log                                        | ✅                                                                                     |
| Security scanning (secrets, PII, prompt injection) | ✅                                                                                     |
| Permission rules (allow / deny / ask)              | ✅ — minus session-scoped grants                                                       |
| Cache-TTL handling                                 | ✅                                                                                     |
| Multi-account pooling and switching                | ❌ with an API key — works via the `opencode-claude-auth` community plugin (see below) |
| Claude Code settings sync                          | ❌ — opencode has its own config                                                       |

## Setup

<Steps>

1. Install opencode and give its Anthropic provider an API key — `/connect`, choose Anthropic, then
   **Manually enter API Key**. Any `sk-ant-api…` key works.

2. In Sentinel, click **Enable** on the **opencode** card. The card shows the exact config file it
   will write (normally `~/.config/opencode/opencode.json`). Sentinel writes one key into it,
   preserving everything else in the file:

   ```json
   {
     "provider": {
       "anthropic": {
         "options": {
           "baseURL": "http://127.0.0.1:47284/v1"
         }
       }
     }
   }
   ```

   The port is the one Sentinel's proxy listens on (47284 by default). The `/v1` suffix matters —
   opencode's Anthropic provider appends `/messages` to the base URL, so a base URL without it
   produces a 404. Once routing is active the card disappears; the on/off control then lives in
   **Settings → General**.

   If your config already had a base URL of its own (a corporate gateway, say), Enable replaces it.
   Sentinel saves the old value in its own state (`~/.sentinel/opencode-state.json`, never in your
   opencode config) and puts it back when you turn routing off. If the config file is a symlink
   (a dotfiles repo, for example), Sentinel writes through the link to the real file and keeps its
   permissions.

3. Restart opencode, then confirm traffic is flowing:

   ```sh
   tail -f ~/.sentinel/daemon.log
   ```

   You should see `POST /v1/messages → 200` lines appear as you use opencode.

</Steps>

## Which config file Sentinel edits

Sentinel resolves opencode's config the way opencode does: `$OPENCODE_CONFIG` if set, otherwise
`$XDG_CONFIG_HOME/opencode/` (default `~/.config/opencode/`), preferring `opencode.jsonc` over
`opencode.json` when both exist.

There is one catch. Sentinel's background service is launched by the Sentinel app, not by your
shell, so it does **not** see environment variables you export only in `~/.zshrc`, `~/.bashrc`, or
similar. If you set `OPENCODE_CONFIG` or `XDG_CONFIG_HOME` there, opencode (started from that shell)
and Sentinel can be looking at different files — Sentinel writes one, opencode reads the other, and
nothing gets routed.

The opencode card (and, once routing is on, the toggle in **Settings → General**) always shows the
path Sentinel writes, so compare it with what opencode uses
(`opencode debug config`). If they differ, either set the base URL by hand in the file opencode
reads, or make the variable visible to GUI apps too (on macOS,
`launchctl setenv OPENCODE_CONFIG /path/to/opencode.json`, then quit and reopen Sentinel; it lasts until you log out).

## If your config has comments

opencode accepts JSONC, and Sentinel will not rewrite a config file that contains real comments —
saving it would silently delete them. In that case the card offers the snippet above to paste in by
hand. (A `.jsonc` file with no actual comments is written normally; Sentinel checks the contents,
not the extension.)

Trailing commas, the other JSONC extension, are fine: Sentinel reads them and writes the file back
without them. A file that is not valid JSON for any other reason is reported as such — not as
"contains comments" — and left untouched until you fix the syntax error.

## Why API-key requests are not pooled

Anthropic gates subscription credentials to Claude Code: the request must carry the
`oauth-2025-04-20` beta flag and Claude Code's own system prompt. Claude Code and the Claude Desktop
app send both, which is why Sentinel can pool accounts for them. opencode sends neither.

Sentinel could forge those markers, and deliberately does not — it identifies its own traffic
honestly and never manufactures a client identity it wasn't given. So on Sentinel's own terms,
opencode with an API key gets the observability and guardrail half, on your own key. (A plugin that
supplies Claude Code's identity itself is a different case — see below.)

## Clients that send their own API key

This applies to any tool you point at Sentinel, not only opencode. A request that carries an
`x-api-key` header and does not identify as Claude Code (Claude Code's `claude-cli/` user agent, or
its OAuth beta flag) is forwarded **with that key**: Sentinel no longer replaces it with a token
from your account pool. Its usage is recorded under the **API key** scope in Metrics rather than
against a pooled account. Claude Code and the Claude Desktop app are unaffected.

If a third-party tool was relying on the old behavior — configured with a placeholder key such as
`dummy` and expecting Sentinel to substitute a real one — it will now get
`401 authentication_error` from Anthropic. Give the tool a real Anthropic API key; Sentinel still
logs, scans, and applies permission rules to its traffic.

## Subscription plans via community plugins

Plugins exist that bring a Claude subscription into opencode by doing the identity work themselves.
Sentinel neither provides nor endorses this — Anthropic's terms gate subscription credentials to
official clients, and opencode's own documentation notes Pro/Max use this way is prohibited. If you
accept that trade-off, the plugins differ in the one way that matters to Sentinel: whether they keep
opencode's normal provider stack or replace the endpoint.

- **`opencode-claude-auth` — verified working alongside Sentinel.** It authenticates with the Claude
  Code credentials already on your machine and honors whatever base URL opencode's provider config
  resolves, so the routing this guide sets up keeps working: its traffic flows through the proxy,
  attributes to your pooled accounts (its requests present Claude identity, so pooling and switching
  apply), and shows up in the request log, security scanning, and Metrics cost/token figures.
  Install it per its README (`"plugin": ["opencode-claude-auth@latest"]`), then enable the opencode
  card as above — no API key step needed.

- **`opencode-with-claude` (Meridian) — bypasses Sentinel.** It starts its own local proxy and
  **overwrites `provider.anthropic.options.baseURL` at startup**, including the value Sentinel
  wrote. With it installed, opencode traffic does not pass through Sentinel at all. Sentinel detects
  this and reports it on the card rather than showing a routed state that isn't true; remove the
  plugin from your opencode config to route through Sentinel.

### Running both side by side

Subscription and API-key billing can coexist in one opencode install. `opencode-claude-auth` scopes
itself to the provider id `anthropic`, so a second custom provider entry is untouched by it:

```json
"anthropic-api": {
  "npm": "@ai-sdk/anthropic",
  "name": "Anthropic (API key)",
  "options": {
    "apiKey": "{env:ANTHROPIC_API_KEY}",
    "baseURL": "http://127.0.0.1:47284/v1"
  },
  "models": {
    "claude-sonnet-5": { "name": "Sonnet 5 (API)" }
  }
}
```

Pick per conversation: `anthropic/…` models bill the subscription (pooled, switched by Sentinel);
`anthropic-api/…` models bill your API key. Both route through the proxy — the API-key traffic
shows up in the Metrics tab under the **API key** scope (the row appears once the first request
lands). Two caveats: this entry's `baseURL` is not managed by Sentinel's enable/disable toggle, and
custom providers need their `models` listed explicitly.

## Troubleshooting

**The card says "opencode is bypassing Sentinel."** A plugin is rewriting the base URL — see
[Subscription plans via community plugins](#subscription-plans-via-community-plugins). Remove it
from the `plugin` array in your opencode config.

**No traffic in the daemon log.** Check the base URL actually ends in `/v1`, and that you restarted
opencode after enabling. `opencode debug config` prints the resolved configuration, including any
value a plugin replaced.

**The card still offers Enable even though the base URL already points at `127.0.0.1:47284`.** That
is deliberate: a base URL on Sentinel's host and port but _without_ the `/v1` path cannot work,
because the AI SDK appends `/messages` to it and Anthropic 404s the result. Sentinel reports that as
not-yet-routed so Enable stays available and repairs the URL, rather than showing a green state on a
config that would fail on every request.

**Requests fail with 401.** Sentinel forwards your key untouched, so a 401 is between opencode and
Anthropic — verify the key with `opencode auth list`. If the key is a placeholder, see
[Clients that send their own API key](#clients-that-send-their-own-api-key).

**Sentinel says it is routed, but opencode traffic never shows up.** Compare the path on the card
(or in **Settings → General**) with what `opencode debug config` reports — see
[Which config file Sentinel edits](#which-config-file-sentinel-edits).

**I turned routing off and my gateway URL is back.** That is intended: Sentinel restores the base
URL it replaced when you enabled routing.
