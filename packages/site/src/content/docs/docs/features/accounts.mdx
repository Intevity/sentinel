The **Accounts** tab is home base. It lists every Claude account you've enrolled (Pro, Max, Team,
Enterprise, or an Anthropic API key), shows which one is currently serving requests, and lets you
switch, tag, pause, or remove them.

![The Accounts tab showing enrolled accounts and the active account in the header](/sentinel/screenshots/accounts-tab.png)

## Enrolling accounts

Click **Add Account** and choose what you're adding: a **Claude subscription** or an
[**API key**](#adding-an-api-key).

For a subscription, Sentinel opens an in-app terminal running `claude setup-token` — the
official Claude Code sign-in — and captures the long-lived token it produces. Complete the browser
sign-in for the account you want to enroll, then give the account a name and (optionally) an
organization label. You can enroll as many accounts as you own.

**Why the name is asked:** setup tokens are inference-only by Anthropic's design. They can't read
your profile, so Sentinel cannot derive the account's email, display name, or organization from the
token — the name and organization you type are how you tell accounts apart in the UI. Both are
editable later, and you can also assign a **color tag** to each account.

### Adding an API key

Choose **API key** to enroll a key from the [Claude Console](https://platform.claude.com/settings/keys)
instead of a subscription. Both kinds of Console key work: a **personal** (or service-account) key,
which starts with `sk-ant-usr`, and a legacy **workspace** key, which starts with `sk-ant-api`.
Paste the key, give the account a name, and Sentinel checks the key with Anthropic before saving it,
so a mistyped or disabled key is caught on the spot.

A personal key that works in more than one workspace has to say which workspace each request acts
in. Enter that workspace's ID (`wrkspc_…`, from the Workspaces page in the Console) in **Workspace
ID**; Sentinel tells you when a key needs one.

An API-key account behaves differently from a subscription:

- **It bills to your API credits.** There's no 5-hour or weekly limit, so its card shows no usage
  bars and it gets no default usage alert.
- **In Auto mode it takes over when your subscriptions run out.** Auto routes to it once no
  subscription account in the pool has quota left, before any account dips into paid extra usage,
  and moves back as soon as a subscription can take requests again. Exclude it from the pool if you
  want it used only when you switch to it yourself.
- **Claude Code keeps its own sign-in.** Sentinel never writes the key into Claude Code's login;
  the proxy sends it to Anthropic as an API key on Claude Code's behalf. Those requests go out as
  plain API requests rather than as Claude Code's, because Anthropic bills Claude Code traffic
  differently and refuses it on some keys with "Credit balance too low" even when the key has
  credits.

If Anthropic stops accepting the key (it was disabled, deleted, or expired), the account shows
**Replace key**, which opens the same form and swaps in a new key while keeping the account's data.

### Editing name and organization

Click **Edit** on any account card to change its display name or organization label at any time —
useful for filling in an organization you skipped during enrollment or fixing a typo'd name. The
change applies immediately across the UI.

<Aside type="note" title="Claude Code CLI required">
  The add flow signs in through the [Claude Code CLI](https://code.claude.com/docs) — free, no
  separate subscription needed. If the `claude` binary isn't installed, the panel shows the official
  one-line installer with a copy button and a **Retry** button. On Windows, Sentinel finds installs
  in `%USERPROFILE%\.local\bin`, npm's global directory, and bun's bin even when they're missing
  from `PATH`.
</Aside>

### Restoring a deleted account

Because setup tokens carry no identity, re-adding an account Sentinel once knew would normally
create a fresh entry. If you removed an account with **Keep Data**, the name step instead offers
**Restore** choices for each deleted account — pick one and the new token attaches to the old
account, bringing back its name, organization, and usage history.

### Re-authenticating

Setup tokens last about a year. When one expires or is revoked (surfaces as upstream 401s — for
example, Claude Desktop reporting rejected credentials), the account shows a **Re-authenticate**
action that runs the same terminal flow and refreshes the credential in place, keeping all of the
account's data.

<Aside type="note" title="Credentials live in the OS keychain">
  Inactive-account credentials are stored under the `Sentinel-credentials` service in your OS
  keychain — never in a plain file. Switching accounts rewrites the active OAuth credential that
  Claude Code reads.
</Aside>

## Switching modes

Open **Settings** and pick a **switching mode**:

- **Off** — you manage the active account by hand from the Accounts tab. The header always shows
  which account is active.
- **Auto** — Sentinel moves the active account for you, so you're not switching manually as windows
  fill up. Each switch safely rewrites the active OAuth credential, and the header always reflects
  the account currently serving requests.

### How Auto chooses

In Auto mode, Sentinel selects from a **pool** of your enrolled accounts. Its strategy,
**earliest-reset**, hard-targets the account whose rate-limit window resets soonest — keeping you on
capacity that's about to refresh rather than capacity you've already spent.

- **Target limit** — choose which window Auto targets under **Settings → Accounts → Target limit**:
  **5-hour** (the default) or **Weekly**. With Weekly, accounts that share a weekly reset are ordered
  by their 5-hour reset.
- **Safety buffer** — Auto stops picking an account once its 5-hour or weekly utilization reaches
  the buffer threshold (95% by default), so a large request can't tip it into overage or a 429.
- **Exhausted accounts are skipped** — an account whose weekly limit Anthropic reports as reached is
  paused until that window resets. If Anthropic lifts the limit early (for example, a one-time usage
  reset), click **Clear limit** on its weekly row in the **Usage** tab; the next request confirms
  the real value.
- **Pool exclusions** — exclude specific accounts from Auto routing (for example, a work account you
  only want used manually) via `poolExcludedIds` in Settings.
- **Paused accounts are skipped** — if [spend caps](/sentinel/docs/features/alerts/#spend-caps)
  pause an account, Auto routes around it until its window resets.

## Account lifecycle

- **Sync** — capture or refresh an account's credentials from Claude Code.
- **Pause / unpause** — temporarily take an account out of the Auto pool.
- **Remove** — soft-delete an account. It moves to **Deleted Accounts** and can be brought back
  later via [Restore](#restoring-a-deleted-account) with all of its data.
- **Purge** — hard-delete an account and all data associated with it.

Removing or purging the account that is currently serving requests is safe: Sentinel hands the
proxy to another enrolled account automatically (or stops injecting credentials when none remain),
so Claude Code and Claude Desktop never keep riding a deleted account's token.

## Pool view

In Auto mode the **Usage** tab can aggregate every pooled account into a single pool view, so you
see combined headroom rather than juggling per-account windows. See
[Usage & rate limits](/sentinel/docs/features/usage/).
